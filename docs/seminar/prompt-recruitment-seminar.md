# 採用セミナー台本生成プロンプト

`【 】` を書き換えて使う。空欄のまま投げても、仮定を明示して書き切るよう指示してある。
元になった構成の詳細版は `docs/seminar/recruitment-indeed-30min.md`。

---

## A. 本体プロンプト（このまま貼る）

```text
あなたは求人広告運用と採用支援の実務経験が豊富なコンサルタントです。
私がこれから登壇する採用セミナーの「話す台本」を作ってください。

━━━━━━━━━━━━━━━━━━━━━━
■ 案件情報
━━━━━━━━━━━━━━━━━━━━━━
・持ち時間: 30分（Q&Aは別枠）
・テーマ: Indeed を中心とした採用／求人広告
・目的: 情報提供。売り込みではない。個別相談への送客は最小限でよい
・形式: 【対面 / ウェビナー】
・スライド: 【作る / 作らない（口頭のみ）】
・登壇者（私）の立場: 【 例: 採用支援会社の代表 】

・聴衆は2タイプが混在している
  A. 経営者陣 — 自社で採用したい（応募→面接→入社→定着）
  B. 人材紹介会社 — 求職者の集客に使っている（応募→登録面談→紹介→決定）
・聴衆の主な業種: 【 】
・想定人数: 【 】
・聴衆の習熟度: 【 Indeedは使ったことがあるが運用はしていない層 】

・出せる実データ: 【 例: 支援◯社の職種別CPAレンジ、タイトル改善前後のCTR、
  返信速度と面接実施率の相関、掲載停止の実例 】
  ※ データは私が後から埋めるので、台本には「ここに入れる」プレースホルダを置いてほしい

━━━━━━━━━━━━━━━━━━━━━━
■ 貫く設計思想（ここは崩さない）
━━━━━━━━━━━━━━━━━━━━━━
1. 混在聴衆を2本の話に分けない。冒頭でこう宣言して1本にまとめる:
   「表示されて、クリックされて、応募されるまでは、AもBも完全に同じ話です。
     違うのは応募の“後ろ側”だけです」
   原稿・タイトル・給与・運用は全員共通。分岐は「応募後のファネル」と
   「許容単価の計算式」だけ。スライドの隅に A / B マークを入れる。

2. 流れは「抽象 → 媒体 → 施策」。ただし冒頭に掲載停止リスクを置く。
   運用の巧拙より「止まらないこと」が先だと最初に言うと、以降の
   「1求人1職種」「事実で書く」がコツではなくリスク管理として聞かれる。

3. 細かいチップスを密度高く入れる。抽象論で終わらせない。
   参加者が翌日1人で実行できる状態がゴール。

4. 目玉スライドを4枚作り、配布資料でも独立した1枚ものにする:
   (1) 掲載が止まる代表パターン＋予防チェックリスト
   (2) 許容応募単価の逆算（A用・B用の2列）
   (3) 「3段＋1」分解（どこが悪いかを数字で切り分ける表）
   (4) 応募後の架電フロー（時間帯・回数・スクリプト）

━━━━━━━━━━━━━━━━━━━━━━
■ 時間配分（合計30分。変えるなら理由を添えて提案して）
━━━━━━━━━━━━━━━━━━━━━━
0:00–2:00   導入: 共通フレーム＋今日持ち帰る3つ
2:00–5:00   第0部: 止まったら全部ゼロ（掲載停止・アカウント停止）
5:00–10:30  第1部: 採用の原理原則（ファネル分解＋許容応募単価の逆算ワーク）
10:30–15:00 第2部: 媒体の地図と Indeed の位置づけ
15:00–26:00 第3部: Indeed 実践施策（原稿・運用・応募後の電話）
26:00–29:00 まとめ: 明日からの3ステップ
29:00–30:00 持ち帰り資料の案内・Q&A導線

━━━━━━━━━━━━━━━━━━━━━━
■ 各パートに必ず入れる要素
━━━━━━━━━━━━━━━━━━━━━━
【導入】
・自己紹介は30秒（社数・職種・エリアの3点のみ）
・問いかけ:「自社の求人を、いま、スマホで求職者と同じ言葉で探して見つけられますか？」
  → 最後の3ステップで回収する
・「今日は網羅しません。3つだけ持って帰ってください」と宣言

【第0部 掲載停止リスク】
・止まる代表パターンを表で（実在しない求人の常時掲載／重複投稿／複数職種の
  詰め込み／タイトルの煽り・記号／実態と異なる条件（歩合の上限を月収として書く）
  ／年齢・性別・国籍の制限表現／応募フローを迂回する外部誘導／求人でないものの
  掲載／多重アカウント・再登録／募集終了の放置）
・アカウント単位で止まると全職種の応募が0になる。止まるのは繁忙期。復帰は即日でない
・「表示が急に落ちたら、原稿を直す前に停止・非表示を疑う」
・法令が絡む部分（年齢制限の原則禁止、性別制限の原則禁止、国籍で絞らない、
  労働条件の明示）は必ず触れる。ただし条文の断定はせず「要確認」と明示
・予防チェックリスト（掲載前チェックシート／NGワードを機械的に潰す／投稿経路を
  1本に統一／募集終了は必ずクローズ／外部誘導しない／止まったら1箇所ずつ直して
  再申請、全面書き直しはしない／Indeed 1本足にしない）
・脅しで終わらせず、この一言で着地させる:
  「止まらないための作業は、全部“いい求人を書くための作業”と同じです」

【第1部 原理原則】
・ファネル図を「応募」で A / B に分岐させて見せる
・Bは段が1つ多い＝同じ応募数でも成果が出にくい構造、と指摘する
・許容応募単価の計算式を渡す（相場を答えない）:
    応募1件の価値 = 1件の成果額 × 応募→成果の転換率
    許容CPA = 応募1件の価値 × 許容率
  A: 成果額＝1年で生む粗利 or 採れないことで失う額 / 転換率＝応募→入社
  B: 成果額＝1決定あたりの手数料 / 転換率＝応募→決定
・30秒の書き出しワークを入れる（「成果額」と「転換率」だけ書かせる）
・締め:「相場より高いか安いかは意味がない。自社の許容単価より高いか安いかだけ」
・採用競合は同業他社ではなく同一商圏・同一給与帯の全求人。Bは紹介会社同士で
  クリック単価を押し上げ合っているので、単価競争ではなく原稿とスピードで勝つ
・採用要件を Must / Want / Negative に割る（Mustが5個以上なら奇跡待ち）

【第2部 媒体】
・媒体は5種類（求人検索エンジン／求人サイト／人材紹介／ダイレクト・SNS／
  リファラル・ハローワーク・自社サイト）。課金形態と向き不向きを表で
・選ぶ基準は値段ではなく「募集の頻度」。年1回なら掲載課金、年中ならクリック課金
・表の「人材紹介」は聴衆Bの事業なので、Aには併用前提で話す（会場が対立しない）
・なぜIndeedから始めるか4点（求職者の入口としての規模／少額で始めて止められる／
  無料枠で原稿の型を作れる／数字が見えるのでファネル分解がそのまま運用になる）
・掲載の2経路（直接投稿 / サイト連携・ATS連携）。順番は直接投稿で勝ちパターンを
  作ってから採用サイトへ。両方やると重複事故になるので経路は1本
・費用は単価ではなく応募単価と成果単価で見る。1〜3月と9〜10月は競合が強い

【第3部 実践施策】
・冒頭に「3段＋1」分解の表を置く:
    表示されない → 職種名・勤務地・予算・掲載状態
    クリックされない（CTR）→ タイトル・給与
    応募されない（CVR）→ 本文冒頭・写真・応募フォーム
    成果にならない → 電話・日程調整・ミスマッチ
  触る順番は「掲載状態の確認 → 原稿 → 対象の拡大 → 予算」。予算増額は最後
・1求人＝1職種＝1勤務地。勤務地は番地まで
・タイトルの型:【職種名】＋【雇用形態】＋【勤務地】＋【訴求を1つだけ】
  求職者が検索する語を使う。社内呼称は通じない。「アットホーム」は1文字も
  仕事をしていない、と言い切る
・給与は必ず数値＋幅。「応相談」は絞り込み検索から丸ごと外れる。
  固定残業代は時間数と金額を明記。歩合の上限を月収として書かない
・本文は求職者の意思決定順（勤務地→給与→シフト→仕事内容→人）。
  冒頭150文字で「誰に・何を・いくらで」を言い切る
・ネガティブ情報を先に出す（応募は減るが後段の実施率と定着率が上がって
  成果単価は下がる）。写真は実際の職場・実際の人
・応募フォームの追加質問は3つまで。履歴書必須は応募率を大きく下げる。
  自動返信に「これから担当者が電話します」と書く
・運用: 少額の日予算で2週間テスト／触るのは1回1箇所／週1回15分の定例で
  表示・CTR・応募・CPA・掲載状態を見る／口コミを放置しない
・★応募後の電話を独立ブロックで厚く:
  - つかみ:「広告費を1円も増やさずに採用数を増やす方法が1つだけあります」
  - なぜ効くか: 応募ボタンを押した直後が一番熱い／複数社に同時応募していて
    最初に電話が通じた会社が勝つ／電話はその場で日程が決まる唯一の手段
  - スピード基準: 1時間以内、理想は5分。応募通知を共有箱に飛ばして当番制
  - 出ない前提の設計: 1回目でつながるのは半分以下／時間帯を変えて2〜3回／
    在職者は昼休みと18〜20時／SMSを先に送ってから架電／留守電は必ず残す
    （会社名・どの求人か・折り返し先・いつ折り返せばいいか）／3回で切り上げ／
    深夜早朝はかけない
  - スクリプト: 名乗る→どの求人への応募か言う→目的は日程だけ→条件交渉は
    会って→「明日の◯時か明後日の◯時」の二択→持ち物と「当日でも変更できます」
  - KPIは「応募当日に架電できた件数の割合」。架電記録を残す。前日リマインド
・面接ハードルを下げる（Web面談可・私服可・15分のカジュアル面談）。
  Bは「登録」を先に出さず、まず案件の話をする
・B向け追加論点: 「登録すれば紹介します」型はCVRが低いので具体案件ベースで出す／
  離脱が二重なので各率を1回測る／許可番号と事業者名の明示、求職者から手数料を
  取らないことの明示／Indeedは実在する求人が前提で登録者募集型は審査で落ちる
  ことがある（最新ポリシーを要確認）
・よくある失敗トップ5でまとめる

【まとめ】
・明日からの3ステップ:
  1) 自社の求人を求職者と同じ検索語でスマホで探す（5分）
  2) タイトルと給与欄だけ直す＋NGワードチェック（30分）
  3) 「応募には1時間以内に電話する」を社内ルールにする（0円）
・Bへの追加1行:「応募→登録面談実施率を、今週1回だけ数えてください」
・締め:「予算を増やす前に、この3つを全部やってください。順番が逆だと、
  同じ失敗に金を払うことになります」

━━━━━━━━━━━━━━━━━━━━━━
■ 絶対に守る制約
━━━━━━━━━━━━━━━━━━━━━━
1. 数字は断定しない。相場を語らず「当社支援実績（◯年◯月時点）」と限定する。
   母数を添える書き方にする
2. Indeed の仕様・課金メニュー・審査基準・無料掲載の露出条件は変わる前提で書く。
   「◯年◯月時点」と添え、細かい最新仕様は質問で受ける建てつけにする
3. 法令に触れる箇所は条文番号を断定せず、「登壇前日に一次情報で再確認」と
   台本の注記に入れる。特に年齢・性別・国籍の制限、労働条件の明示、
   有料職業紹介の明示義務
4. 売り込みは最後の1回・1分以内。実質は資料の最終ページに1行置くだけにする
5. 中身のない語（「アットホーム」「明るい職場」「やりがい」）を良い例として
   出さない。悪い例として使う
6. スライドは15〜20枚が上限。1枚1メッセージ。読ませるスライドは作らない
7. 掲載停止の事例は社名が分からない粒度に丸める（「◯◯業の数十名規模の会社で」）
8. 脅しや煽りで終わるパートを作らない。必ず打ち手に着地させる

━━━━━━━━━━━━━━━━━━━━━━
■ 出力してほしいもの（この順で）
━━━━━━━━━━━━━━━━━━━━━━
1. タイムテーブル表（時間・パート・狙い）
2. スライド一覧（番号／タイトル／そのスライドの1メッセージ／A・Bどちら向けか／
   割り当て時間）
3. パートごとの台本。話し言葉で書く。言い切るフレーズは太字。
   スライド番号と対応させる。「ここで実データを入れる」プレースホルダを明示
4. 配布資料4点セットの中身（3段＋1分解／許容CPA計算シート／掲載前チェック
   シート（NGワード表＋必須記載項目）／タイトルの型＋架電フロー）
5. 想定Q&Aと回答（最低7問。「クリック単価の相場は？」には相場を答えず
   許容単価の話に戻す回答を用意）
6. 事前準備チェックリスト（検索結果のスクショ、確認すべき最新仕様と法令、
   実データの整理、リハーサルで測る時間）
7. 私に足りていない情報の質問リスト（最大5つ。台本を良くするために必要な順）

━━━━━━━━━━━━━━━━━━━━━━
■ 進め方
━━━━━━━━━━━━━━━━━━━━━━
・【 】が空欄の項目は、もっとも一般的な想定を仮定として明示した上で書き切ること。
  質問して止まらない
・30分に収まるかを最後に自己チェックし、オーバーしていれば削る候補を3つ挙げる
```

## B. テコ入れ用の追い込みプロンプト（本体の後に投げる）

```text
■ 厚さを変える
・第0部（掲載停止）を◯分に増やし、そのぶん第2部（媒体）を削って
・第3部の「応募後の電話」を、これだけで5分話せる密度にして
・第1部の許容CPA計算を、電卓なしで会場でできるところまで簡単にして

■ 聴衆に寄せる
・聴衆の業種を【 】に絞り、例示・職種名・検索キーワードを全部そこに差し替えて
・Bタイプ（人材紹介）の参加者が7割だとしたら、どこを増減すべきか提案して
・経営者向けに「採れないことで失っている額」の計算例を具体的な数字で作って

■ 言葉を強くする
・各パートの「言い切るフレーズ」を3案ずつ出して。会場がメモを取る言い方で
・冒頭2分をそのまま読める原稿にして。つかみの1文は5案出して
・専門用語（CTR・CVR・CPA）を、初めて聞く人に1行で説明する言い方を作って

■ 資材を作る
・配布用の掲載前チェックシートを、A4片面1枚に収まる形で作って
・求人タイトルの良い例／悪い例を、【業種】で10組作って
・架電スクリプトを、そのまま印刷して電話の横に置ける形にして
・スライドごとの読み上げ台本（1枚あたり60〜90秒）にばらして

■ 削る
・25分に収めるとしたらどこを削る？優先順位をつけて3案出して
・スライドを12枚に減らすなら、どれを統合する？

■ 検証する
・この台本で、参加者が翌日実行できないものが残っていないか点検して
・断定しすぎている箇所、最新仕様の確認が必要な箇所を全部リストアップして
・Bタイプの参加者が「自社のことを分かっていない」と感じそうな箇所を指摘して
```

## C. 使い方のメモ

- **A を投げる前に `【 】` を埋める**。特に「聴衆の主な業種」と「出せる実データ」の
  2つで出力の質が大きく変わる。業種が決まると例示と検索キーワードが具体化する。
- 実データは後から埋める前提でプレースホルダを置かせているので、**Aの時点で
  数値を用意しなくてよい**。
- 出てきた台本は **B の追い込みプロンプトで削る／厚くする**のが早い。
  最初から完璧を狙うより、厚めに出させて削るほうが30分に収まる。
- 制約7番（社名を丸める）と制約3番（法令の一次情報確認）は消さないこと。
  ここを外すと登壇リスクが上がる。
